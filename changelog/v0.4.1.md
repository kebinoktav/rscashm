# RSCashM 0.4.1

This release improves encrypted ledger handling, password security, and file-saving reliability.

## Added
- Added a **Lock** button to re-lock an encrypted ledger after it has been unlocked.
- Transaction data is now cleared from both the main application state and the file-reading state when a ledger is locked.
- Application passwords are now stored using `Zeroizing<String>` to clear the password buffer when its value is reset or its state is dropped.
- Ledger and configuration files are now saved through temporary files, followed by an atomic rename. On Linux, temporary files are created with `0600` permissions.

## Fixed
- Prevented direct overwriting of ledger files. If writing to a temporary file fails before replacement, the previous ledger file remains intact.
- Prevented plaintext data from remaining in memory when a ledger is locked or when the active file is replaced or detected as encrypted.
- Ensured that the file-reading state's data copy remains empty after a Lock action.

## Password Security
- The password field uses secure input mode, preventing characters from being displayed while typing. This existing behavior has been retained.
- Zeroization reduces the time passwords remain in memory, but does not guarantee the removal of every possible copy created by the runtime or operating system.

## Installation Paths

Default installation paths when using the default prefix (`~/.local`):

- **Launcher:** `~/.local/bin/rscashm`
- **Application binary:** `~/.local/lib/rscashm/rscashm`
- **Desktop entry:** `~/.local/share/applications/rscashm.desktop`
- **Application icon:** `~/.local/share/pixmaps/rscashm.png`
